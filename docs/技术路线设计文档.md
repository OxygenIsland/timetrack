# 🧩 技术路线设计文档（单人全栈版）

> **调研范围**：智能监控/AI 摄像头行业软件主流技术栈、海康威视 AI 摄像头算法集成、跨摄像头协同感知与去重、多人识别工时统计、单人全栈桌面应用技术路线。
> **设计目标**：单人前后端全栈，部署在一台 Windows 11 主控终端上（i7-14700 + RTX 5060Ti 16G + 32GB），与 4 路海康 AI 摄像头深度集成。
> **设计原则**：能复用的轮子坚决不造、生态成熟优先、单人能维护、与 AI 摄像头厂商生态契合。

## 三、前端技术路线（Electron）

### 3.1 为什么选 Electron（对比 Tauri / WPF / Qt / Wails）

| 框架 | 包体积 | 启动速度 | 生态丰富度 | 上手难度 | AI/视频库支持 | 推荐度 |
|------|-------|---------|-----------|---------|-------------|--------|
| **Electron** | 120-280MB | 1-3s | ⭐⭐⭐⭐⭐ 极厚 | ⭐ 最低 | ⭐⭐⭐⭐⭐ 极全 | ✅ **首选** |
| Tauri 2.0 | 3-30MB | <100ms | ⭐⭐⭐⭐ 成长中 | ⭐⭐⭐⭐ 需 Rust | ⭐⭐⭐ 中 | ⚠️ 备选（若你会 Rust） |
| WPF | 1-95MB | 快 | ⭐⭐⭐ 中 | ⭐⭐⭐ 仅 Windows | ⭐⭐ 少 | ⚠️ 可行但视频库少 |
| Qt | 20-80MB | 较快 | ⭐⭐⭐ 中 | ⭐⭐⭐⭐ 需 C++ | ⭐⭐⭐ 中 | ❌ 单人不友好 |
| Wails | 8-35MB | 中 | ⭐⭐ 较小 | ⭐⭐⭐ 需 Go | ⭐⭐ 少 | ❌ 单人需双语言栈 |

**结论**：单人全栈 + AI 视频场景，**Electron 的 Web 生态红利**是不可替代的——npm 上视频、图表、UI 组件库超过 250 万，AI 流媒体相关的库（如 react-player、hls.js、whep-client、video.js）应有尽有。而 Tauri 虽然更轻，但需要 Rust，对单人前后端开发是负担。**WPF**只支持 Windows 生态确实深，但视频/Web 生态薄，集成 WebRTC 流很麻烦。

### 3.3 视频播放方案（核心难点）

**问题**：海康摄像头输出 RTSP（H.264/H.265），浏览器**不能直接播放**。

**方案**：用 **MediaMTX**（开源 RTSP→WebRTC 网关）把 RTSP 流转成 WebRTC，浏览器通过 **WHEP** 协议用 fetch + RTCPeerConnection 直接拉流，延迟 300-500ms。

```typescript
// 浏览器端拉流代码（极简）
async function playCamera(whepUrl: string, videoEl: HTMLVideoElement) {
  const pc = new RTCPeerConnection();
  pc.ontrack = (e) => { videoEl.srcObject = e.streams; };
  const offer = await pc.createOffer({ offerToReceiveAudio: false, offerToReceiveVideo: true });
  await pc.setLocalDescription(offer);

  const res = await fetch(whepUrl, {
    method: 'POST',
    headers: { 'Content-Type': 'application/sdp' },
    body: offer.sdp!,
  });
  const answer = await res.text();
  await pc.setRemoteDescription({ type: 'answer', sdp: answer });
}
```

**优势**：
- ✅ 浏览器**免插件**
- ✅ 延迟 <500ms（满足实时监控）
- ✅ 4 路同时预览稳定
- ✅ 不依赖摄像头固件（不像 HIKEP 需要 V5.6.0+）

### 4.4 关键模块设计

#### 4.4.1 B1 - AI 算法编排引擎

**架构**：参考行业两阶段方案

```python
# app/ai/pipeline.py
class CameraPipeline:
    """单路摄像头的推理 Pipeline"""
    def __init__(self, cam_id, rtsp_url, roi_polygon):
        self.detector = YOLOv8('yolov8n.pt')           # 人员检测
        self.tracker = ByteTracker()                    # 单摄像头跟踪
        self.reid_extractor = OSNet()                   # ReID 特征
        self.reid_gallery = ReIDGallery(max_age=300)    # 特征库（5 分钟记忆）
        self.zone_judge = ZoneJudge(roi_polygon)         # 区域归属判定
    
    async def process_frame(self, frame):
        # Step 1: 检测
        detections = self.detector(frame, classes=[0])  # 仅检测人
        # Step 2: 单摄像头跟踪
        tracks = self.tracker.update(detections)
        # Step 3: ReID 特征提取
        for track in tracks:
            track.feature = self.reid_extractor(frame, track.bbox)
        # Step 4: 跨摄像头 ReID 匹配
        global_ids = self.reid_gallery.match(tracks, cam_id=self.cam_id)
        # Step 5: 区域归属 + 事件生成
        events = self.zone_judge.update(tracks, global_ids, timestamp=now())
        return events  # 进入/离开事件
```

**多路并行**：用 `asyncio.create_task` 或 `multiprocessing.Pool` 跑 4 个 Pipeline（GPU 足够时可同进程跑）。

```python
# app/ai/orchestrator.py
async def start_orchestrator():
    pipelines = [
        CameraPipeline(cam_id=1, rtsp_url=CAM1_RTSP, roi_polygon=ROI_1),
        CameraPipeline(cam_id=2, rtsp_url=CAM2_RTSP, roi_polygon=ROI_2),
        CameraPipeline(cam_id=3, rtsp_url=CAM3_RTSP, roi_polygon=ROI_3),
        CameraPipeline(cam_id=4, rtsp_url=CAM4_RTSP, roi_polygon=ROI_4),
    ]
    # ReID Gallery 共享（跨摄像头匹配）
    shared_gallery = ReIDGallery(max_age=300)
    for p in pipelines:
        p.reid_gallery = shared_gallery
    
    # 并行启动
    await asyncio.gather(*(p.run() for p in pipelines))
```

**关键算法**（参考行业方案）：
- 检测：YOLOv8n（轻量）或 YOLOv8s（精度）
- 单摄像头跟踪：ByteTrack（遮挡鲁棒，MOTA 比 DeepSORT 高）
- ReID：OSNet（轻量，ICCV 2019 经典）
- 跨摄像头分配：ReID cosine similarity + Hungarian + 时空门控（区域转移表）
- 重复数据剔除：跨摄像头 ReID 后，4 路同一人只产生一次事件

### 5.1 海康摄像头对接方案

| 能力 | 方案 | 备注 |
|------|------|------|
| **视频流** | RTSP（主/子码流） | `rtsp://admin:pass@ip:554/Streaming/Channels/101`（主）/201（子） |
| **AI 算法集成** | 海康 AI 开放平台 + ISAPI（AIOpenPlatform） | `PUT /ISAPI/Intelligent/AIOpenPlatform/algorithmModel/loading/` 下发模型 |
| **设备管理** | ISAPI（HTTP + Digest Auth + XML） | 详见海康官方 AI 开放平台 |
| **录像回看** | 海康 SDK（HCNetSDK Python 版） | 查询历史、按时间下载 |
| **PTZ/事件订阅** | ISAPI Event Notification | 可选 |

**模型部署策略**（两种选其一）：
- **方案 A**：直接用海康 AI 摄像头内置算法 → ISAPI 订阅报警事件。简单、零开发。
- **方案 B**：用我方 YOLOv8 算法（部署在后端）→ 主控终端做推理。灵活、可定制。**✅ 推荐**

> 推荐方案 B 的原因：原文档里"4 摄像头协同感知"需要做跨摄像头 ReID，海康内置算法不支持，必须自己实现。

### 5.3 实时数据推送（WebSocket）

```python
# app/ws/manager.py
class WSManager:
    """WebSocket 连接管理器，支持按频道订阅"""
    def __init__(self):
        self.connections: dict[WebSocket, set[str]] = {}
        self.locks = defaultdict(asyncio.Lock)
    
    async def connect(self, ws: WebSocket, channels: list[str]):
        await ws.accept()
        self.connections[ws] = set(channels)
    
    async def broadcast(self, channel: str, data: dict):
        """推送给所有订阅了该频道的客户端"""
        msg = json.dumps({"channel": channel, "data": data, "ts": now()})
        dead = []
        for ws, channels in self.connections.items():
            if channel in channels:
                try:
                    await ws.send_text(msg)
                except:
                    dead.append(ws)
        for ws in dead:
            self.connections.pop(ws, None)
```

**推送节奏**：
- `personnel_realtime`：人员计数变化时推送（事件驱动，不轮询）
- `workhours_realtime`：工时累计变化时推送（每 60 秒一次，或进入/离开事件触发）
- `system_status`：系统状态（每 10 秒一次心跳）

## 八、关键技术风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| **H.265 浏览器兼容性** | MediaMTX 转 WebRTC 失败 | 用 FFmpeg 强制转 H.264（runOnReady） |
| **4 路同时解码 + AI 推理的 CPU/GPU 压力** | 实时性不达标 | 用子码流（640×360）做 AI 推理；主码流仅回看时调取 |
| **ByteTrack 在遮挡密集场景下 ID 切换** | 重复计数 | 用 ReID + 时空门控二次校验 |
| **OSNet ReID 在工装相似时混淆** | 跨摄像头误关联 | 配合摄像头拓扑 + 区域转移表 + 时间窗门控 |
| **MediaMTX 在 Windows 上的稳定性** | 流断 | MediaMTX 本身有自动重连；额外加 watchdog 监控 |
| **PostgreSQL + TimescaleDB 在 Windows 上的安装** | 部署门槛 | 用 Docker Desktop for Windows，或预编译 zip 版 PostgreSQL |
| **Electron 包体积 200MB+** | 安装慢 | 内部工具可接受；二期可改 Tauri 减小体积 |
| **单人维护压力大** | 进度风险 | 严格控制一期范围；MCP/AI 助手提高编码效率 |

## 九、替代方案对比（如果时间不允许做 AI 集成）

**简化路径**（当算法侧进度受阻时）：
- 跳过自主 YOLOv8 推理，直接用**海康摄像头内置算法** + **ISAPI 订阅报警事件**
- 后端只做：事件接收、存储、工时计算、报表生成
- 这样后端工作量可以减少一半，但**失去跨摄像头协同感知**能力（一期只能"被动接受"4 路各自的事件）

**建议**：先按本文档方案 A 推进，准备 B 方案作为降级预案。
