# ⚙️ 后端需求拆分（一期配套）

> **拆分原则**：根据 `前端需求-核心需求.md` 中一期 4 个核心模块（M1-M4）的依赖关系，推导出后端需要提供的支撑能力。
> **后端职责边界**：负责 AI 算法集成、数据采集、业务计算、API 提供、数据存储——所有"前端需要但前端不做"的事。
> **部署环境**：与前端共用智能主控终端（Windows 11 / i7-14700 / RTX 5060Ti 16G / 32GB / 512GB SSD + 2TB HDD），但可部署为独立服务（如 Windows Service / 后台进程）。

---

## 一、后端模块总览

| 编号 | 模块名称 | 支撑前端模块 | 优先级 |
|------|---------|-------------|--------|
| B1 | AI 算法集成与调度 | M1, M2, M3 | P0 |
| B2 | 视频流接入与转发 | M1 | P0 |
| B3 | 人员事件检测与记录 | M2 | P0 |
| B4 | 工时计算引擎 | M3 | P0 |
| B5 | 数据存储与查询 | M2, M3, M4 | P0 |
| B6 | 报表生成服务 | M4 | P0 |
| B7 | 系统状态监控 | M1 | P0 |
| B8 | 配置管理 | M3 | P0 |

## 二、详细功能需求

### B1 - AI 算法集成与调度

| 编号 | 功能项 | 详细描述 | 验收标准 |
|------|--------|----------|----------|
| B1-01 | 摄像头算法接入 | 接入 4 台海康 AI 摄像头，加载定制算法模型（人员检测 + 工装识别） | 4 路同时稳定运行 |
| B1-02 | 算法参数配置 | 支持远程/本地配置检测区域、检测灵敏度、置信度阈值 | 配置生效时间 ≤30秒 |
| B1-03 | 跨摄像头协同感知 | 实现 4 摄像头单量化区域协同感知，覆盖盲区 | 与算法侧协同实现 |
| B1-04 | 重复数据剔除 | 跨摄像头同一人员目标关联，剔除重复识别数据 | 重复率 ≤5% |
| B1-05 | 算法结果推送 | 将算法分析结果（人员位置、类别、置信度、时间戳）通过内部通道推送给业务模块 | 延迟 ≤500ms |
| B1-06 | 模型更新机制 | 支持算法模型远程更新/回滚 | 失败可回滚 |

---

### B2 - 视频流接入与转发

| 编号 | 功能项 | 详细描述 | 验收标准 |
|------|--------|----------|----------|
| B2-01 | RTSP 视频流接入 | 拉取 4 路 AI 摄像头的 RTSP 视频流 | 稳定拉流，断流自动重连 |
| B2-02 | 视频流转发 | 将视频流转发给前端，供 M1 多窗口预览 | 转发延迟 ≤2秒 |
| B2-03 | 历史录像存储 | 接入 NVR，存储并提供历史录像回看能力（M2-04） | 至少保留 30 天录像 |
| B2-04 | 视频片段截图 | 根据时间戳拉取指定片段的视频/截图 | M2-04 回看功能依赖 |

---

### B3 - 人员事件检测与记录

| 编号 | 功能项 | 详细描述 | 验收标准 |
|------|--------|----------|----------|
| B3-01 | 人员进入事件 | 检测到新人员进入胎位/量化区域时，生成进入事件 | 时间精度 ≤1秒 |
| B3-02 | 人员离开事件 | 检测到人员离开时，生成离开事件 | 时间精度 ≤1秒 |
| B3-03 | 区域归属判定 | 判定人员当前所在的胎位/工件 | 判定准确 |
| B3-04 | 人员类别标识 | 依据算法识别结果标注管理/施工 | 与算法输出对齐 |
| B3-05 | 事件去重 | 同一人员短时间内在同一区域反复触发要合并 | 避免流水噪声 |
| B3-06 | 事件持久化 | 进出事件写入数据库 | 不丢失、不重复 |

---

### B4 - 工时计算引擎

| 编号 | 功能项 | 详细描述 | 验收标准 |
|------|--------|----------|----------|
| B4-01 | 有效工时规则解析 | 解析"有效工时判定规则"（如停留 ≥N 分钟） | 配置即生效 |
| B4-02 | 班次时间管理 | 支持配置班次时间段（早班/晚班/夜班） | 多班次支持 |
| B4-03 | 实时工时累计 | 根据进出事件实时累计当前班次工时 | 秒级刷新（M3-05） |
| B4-04 | 多维度聚合 | 按分组/人员类别/人员三个维度聚合工时 | 数据准确 |
| B4-05 | 工时修正接口 | 提供 API 让前端记录人工修正（M3-06） | 修正留痕 |
| B4-06 | 工时计算结果存储 | 计算结果持久化，供前端和报表使用 | 历史可追溯 |

---

### B5 - 数据存储与查询

| 编号 | 功能项 | 详细描述 | 验收标准 |
|------|--------|----------|----------|
| B5-01 | 数据库选型与部署 | 选择并部署数据库（建议 SQLite / PostgreSQL / TimescaleDB） | 满足吞吐与查询性能 |
| B5-02 | 数据模型设计 | 设计人员、事件、工时、分组等核心表结构 | 可扩展 |
| B5-03 | 实时数据写入 | 高频写入人员进出事件（预估峰值 100+ events/分钟） | 不丢数据 |
| B5-04 | 历史数据查询 | 支持多条件组合筛选（M2-03、M4-04） | 响应 ≤2秒 |
| B5-05 | 数据保留策略 | 设计数据保留周期（热数据 30 天 / 冷数据归档） | 与存储容量匹配 |
| B5-06 | 数据备份机制 | 每日自动备份本地数据库 | 备份可恢复 |

### B6 - 报表生成服务

| 编号 | 功能项 | 详细描述 | 验收标准 |
|------|--------|----------|----------|
| B6-01 | 日报生成 | 生成当日工时报表（按分组/人员类别/人员维度） | 数据完整 |
| B6-02 | 周报生成 | 当周工时汇总 + 周对比 | 数据完整 |
| B6-03 | 月报生成 | 当月工时汇总 + 月对比 + 人员排行 | 数据完整 |
| B6-04 | 多维筛选生成 | 支持自定义筛选条件生成报表 | 数据准确 |

| B6-07 | 异步导出任务 | 导出任务异步执行，避免阻塞接口 | 进度可查询 |

## 三、非功能性需求（后端必满足）

| 编号 | 需求项 | 指标 |
|------|--------|------|
| NF-B01 | 系统稳定性 | 连续运行 7×24 小时无故障 |

| NF-B09 | 故障恢复 | 服务异常自动重启，恢复时间 ≤60 秒 |

## 四、外部接口契约（后端必须提供给前端）

### 4.1 实时数据 API

| 接口名称 | 方法 | 路径（建议） | 用途 |
|---------|------|--------------|------|
| 人员实时数据 API | GET | `/api/v1/personnel/realtime` | M1 看板实时刷新 |
| 系统状态 API | GET | `/api/v1/system/status` | M1 看板状态栏 |

### 4.2 历史数据 API

| 接口名称 | 方法 | 路径（建议） | 用途 |
|---------|------|--------------|------|
| 历史事件查询 API | GET | `/api/v1/events/history` | M2 人员记录查询 |
| 工时查询 API | GET | `/api/v1/workhours/query` | M3 工时数据查询 |
| 多维筛选查询 API | GET | `/api/v1/reports/query` | M4 报表筛选 |

### 4.3 写操作 API

| 接口名称 | 方法 | 路径（建议） | 用途 |
|---------|------|--------------|------|
| 工时统计提交 API | POST | `/api/v1/workhours/submit` | M3 工时数据提交/更新 |
| 工时修正 API | POST | `/api/v1/workhours/correct` | M3-06 人工修正 |
| 配置更新 API | POST/PUT | `/api/v1/configs/*` | M3-01 规则配置 |

### 4.4 报表导出 API

| 接口名称 | 方法 | 路径（建议） | 用途 |
|---------|------|--------------|------|
| 报表导出 API | POST | `/api/v1/reports/export` | M4 触发导出 |
| 导出任务状态查询 | GET | `/api/v1/reports/export/{taskId}/status` | 查询异步导出进度 |
| 导出文件下载 | GET | `/api/v1/reports/export/{taskId}/download` | 下载生成的文件 |

### 4.5 视频流接口

| 接口名称 | 方法 | 路径/协议 | 用途 |
|---------|------|-----------|------|
| 视频流转发 | RTSP / WebSocket | `rtsp://...` 或 `ws://...` | M1 多窗口预览 |
| 历史录像回看 | RTSP / HLS | `/api/v1/video/playback` | M2-04 视频片段回看 |

## 八、技术选型建议（参考）

| 维度 | 建议 | 理由 |
|------|------|------|
| 后端语言 | Python（FastAPI）或 C# (.NET) | Python 与 AI 生态契合度高；C# 与 Windows 桌面集成佳 |
| 数据库 | PostgreSQL / SQLite（一期） | 数据量不大时 SQLite 足够，后期可平滑迁移到 PostgreSQL |
| 时序数据 | 可选 InfluxDB / TimescaleDB | 工时统计、事件流水有强时序特征 |
| 消息队列 | Redis Streams / 内置队列 | 一期数据量不大，简单队列即可 |
| 报表库 | Pandas + Openpyxl（Excel） + ReportLab（PDF） | Python 生态成熟 |
| 部署方式 | Windows Service / NSSM 托管 | 与 Windows 11 主控终端集成 |
| API 协议 | RESTful + JSON | 主流、易对接 |
